# Relic dataset plan

Research checked **10 September 2026**, across ten focused reviews. Build a small maintained reference foundation, then add specialist products for a named analyst question. Do not turn the research catalogue into a mandatory installation list. The main improvement over the inherited files is traceable source records and controlled updates, not a larger pile of coordinates.

[catalogue.json](catalogue.json) is the detailed acquisition registry: publisher and documentation links, access locators, formats, identifiers, rights, coverage, update behavior and join limitations. Its entries describe researched candidates. No external dataset was bulk-downloaded, reconciled or accepted into Relic during this review. geoBoundaries and imagery collection metadata were sampled; verification is stated per entry. A metadata/documentation check is not a successful import or a guarantee of present endpoint availability.

The custom X and Flightradar24 integrations and their mandatory proxy routing remain fixed. KeelWatch remains the sole ship observation/history source. Port geography and economic statistics supplement it; they do not establish vessel movements. Existing Copernicus OGC imagery remains the initial viewing route. See [SOURCE_INTERFACES.md](../docs/REFERENCE_DATA.md).

## 1. What to build first

| Delivery | Selected data | Purpose and boundary |
| --- | --- | --- |
| Foundational reference | GeoNames names/aliases; geoBoundaries **gbOpen** for selected countries/levels; Natural Earth for small-scale display | Search and resolve places, scope investigations and draw lightweight context. Retain source-specific boundaries and precision. |
| First facility workflow | OurAirports when airports matter; NGA WPI plus UN/LOCODE when ports matter | Source identities and general locations. WPI/UN/LOCODE rights and release details need resolution before the affected bulk-use/export operation. Neither a port code nor airport location proves military purpose or current operation. |
| Energy investigations | GEM Global Integrated Power Tracker; selected fixed-asset oil/gas trackers later | Facility/unit status as a dated publisher assertion. Keep site, unit and project/phase separate. |
| Existing observation modules | One planned GDACS/institutional advisory path first; USGS and FIRMS as selected contextual expansion | Bounded dated events/detections and revisions. These are separate evidence families, not static map references. |
| Investigation-specific extensions | Regional infrastructure, imagery acquisitions/terrain, curated conflict history, entity context and population exposure | Enable only the products and geographic/time windows needed. Each has separate semantics, rights and refresh cost. |

The first row is the default reference foundation after acceptance. Other rows describe expansion order, not automatic acquisition. Each enabled source has an explicit area/class/time scope, maximum work size, retention policy, freshness rule and recovery path. Start with a selected area rather than a browser-loaded world inventory. Use the fictional fixture to build the workflow before importing real evidence.

## 2. Decisions across the researched domains

### Places and administrative geography

**Select GeoNames + geoBoundaries gbOpen + Natural Earth.** GeoNames provides stable `geonameid` values and multilingual aliases; use `alternateNamesV2` for language and historical-name flags instead of flattening the shortcut alias string. Its administrative codes are not uniformly ISO; keep the documented FIPS/ISO exceptions. Country extracts can bound acquisition. A modification date is an edit date, not the date a place began to exist. [GeoNames dump contract and CC BY notice](https://download.geonames.org/export/dump/readme.txt).

geoBoundaries separates source year, source update, build date and boundary identity. The sampled current USA ADM1 metadata represented **2018**, with 2023 source/build dates. This is why a current catalogue URL cannot mean current legal geography. Import full geometry for analysis and a separately identified simplified display where useful. Natural Earth's public-domain layers are appropriate for fast locator maps; their scale and political viewpoint are cartographic choices. [geoBoundaries API](https://www.geoboundaries.org/api.html), [Natural Earth terms](https://www.naturalearthdata.com/about/terms-of-use/).

Overture Places/Divisions are optional enrichment after release and crosswalk handling exists. Keep them separate: Places and Divisions have different source/licensing arrangements; Divisions also shares lineage with other reference sources. Defer the entire OSM planet in favour of scoped extracts. GADM is not a reusable default because its stated licence restricts commercial use and redistribution; Who's On First is useful when its concordances answer a specific identity problem. [Overture attribution](https://docs.overturemaps.org/attribution/), [GADM licence](https://gadm.org/license.html), [Who's On First downloads](https://www.whosonfirst.org/download/).

**OSM, Geofabrik and Nominatim have different roles.** OSM supplies the underlying geographic records; Geofabrik distributes regional extracts, normally refreshed daily; Nominatim builds a search/reverse-geocoding index from OSM data. Relic can import regional `.osm.pbf` files directly for named places, multilingual aliases, facilities, roads/railways, buildings and land/water context without deploying Nominatim. Preserve the selected tags and original geometry, and use accepted records in local search, nearby-reference queries and spatial association. The regional extract is an input snapshot, not proof of current operating status. [Geofabrik downloads](https://download.geofabrik.de/), [Nominatim import model](https://nominatim.org/release-docs/latest/admin/Import/).

Regional Geofabrik PBF is the owner's confirmed choice for this enrichment path. Implement it when regional OSM coverage is introduced, with areas explicitly selected rather than automatically downloading the world. The [acquisition contract](../docs/REFERENCE_DATA.md#regional-geofabrik-pbf-acquisition) supplies the exact discovery and processing details; convenience GIS exports are not the primary input.

Nominatim is an **optional later geocoding engine**, not another independent dataset or a selected initial service. Evaluate a self-hosted regional instance if address-level search, address hierarchy or reverse geocoding materially outperforms the initial local resolver on representative queries. Its results share OSM lineage with directly imported extracts. No public Nominatim dependency is selected: the public endpoint caps traffic at one request per second and prohibits autocomplete and systematic area/POI harvesting; those restrictions concern that public service, not self-hosted instances. [Public-service policy](https://operations.osmfoundation.org/policies/nominatim/). Neither a Nominatim instance nor a Geofabrik importer has been built or run in this handoff.

### Ports, maritime geography and connectivity

**Prefer NGA World Port Index for port/terminal descriptions and UN/LOCODE for trade-location crosswalks.** Preserve `wpinumber` separately from UN/LOCODE. A UN/LOCODE location may contain a port and other functions; it is not a berth identity or facility footprint. Status/change fields matter, including unvalidated requests. The observed release link in the catalogue is **2025-1**, an example located during research, not an assertion that it is the latest release. [WPI publication](https://msi.nga.mil/Publications/WPI), [UN/LOCODE publications](https://unlocode.unece.org/publications/), [attribute definitions](https://unlocode.unece.org/docs/data-attributes/).

WPI's dataset-specific redistribution terms were not established; UN/LOCODE's standard licence and site-use wording need to be reconciled for the intended operation. Keep those dependencies explicit. The difficult WPI service locator, layer and query-limit discovery are documented in `docs/SOURCES.md` and the catalogue, including the failed direct fetch. Do not infer a validated working API from a search-indexed service description.

MarineRegions EEZ v12 is optional jurisdictional context. It includes methodological constructions, disputes and internal/archipelagic waters; show its source interpretation rather than asserting an uncontested legal boundary. GSHHG is an optional static coastline alternative, with its 2017 vintage disclosed. UNCTAD's port connectivity index is quarterly economic context, not live traffic. None validates the inherited chokepoint traffic estimates. [EEZ methodology](https://www.marineregions.org/eezmethodology.php), [GSHHG](https://www.soest.hawaii.edu/pwessel/gshhg/), [UNCTAD connectivity](https://unctadstat.unctad.org/insights/theme/271).

### Airports and aviation reference

**Use OurAirports for general airport identity and geography.** Its public-domain CSVs include internal identity, airport codes, type and location. Keep code namespaces separate and preserve closed/heliport/seaplane distinctions. Community-maintained completeness does not establish military classification or active traffic. [OurAirports data and definitions](https://ourairports.com/data/).

FAA NASR is a useful U.S. supplement with effective **28-day cycles**; select the actual effective release rather than hardcoding the example August 2026 file. The FAA aircraft register adds U.S. registration assertions, not a global operator/beneficial-owner truth table. Do not collapse an airframe, registration, callsign and flight occurrence. ICAO reference services are optional account/licence-dependent resources. Defer the paid CAA G-INFO download until a specific U.K. need justifies it. None replaces the custom Flightradar transport. [FAA NASR subscriptions](https://www.faa.gov/air_traffic/flight_info/aeronav/aero_data/NASR_Subscription/), [FAA registry files](https://www.faa.gov/licenses_certificates/aircraft_certification/aircraft_registry/releasable_aircraft_download), [ICAO data services](https://dataservices.icao.int/), [G-INFO download](https://www.caa.co.uk/aircraft-register/g-info/g-info-download/).

### Energy and nuclear facilities

**Prefer GEM's Global Integrated Power Tracker for a new power-facility layer.** Preserve its release, source links, exact/approximate geolocation, inclusion thresholds and site/unit identities. Its operating and project statuses are research classifications at a given date. Add GEM fixed oil/gas extraction, pipeline and LNG-terminal products only when required; their releases and grains differ. Select fixed assets here, keeping ship observations with KeelWatch. [GIPT](https://globalenergymonitor.org/projects/global-integrated-power-tracker), [GEM data licence](https://globalenergymonitor.org/creative-commons-license), [gas infrastructure](https://globalenergymonitor.org/projects/global-gas-infrastructure-tracker).

IAEA PRIS is valuable corroboration for civil power reactors, conditional on the intended access/reuse rights. It does not inventory every research, enrichment, fuel-cycle or other nuclear-related site. EIA-860 and refinery data are optional U.S. checks with plant/generator/refinery grains. **Do not use WRI Global Power Plant Database as the current baseline:** its official repository says maintenance stopped and no updates were planned as of early 2022. Retain it only for historical comparison if needed. [PRIS](https://pris-stats.iaea.org/), [EIA-860](https://www.eia.gov/electricity/data/eia860/), [EIA refineries](https://www.eia.gov/petroleum/refinerycapacity/), [WRI maintenance notice](https://github.com/wri/global-power-plant-database).

### Buildings, transport and fixed infrastructure

**Choose a regional Geofabrik OSM extract when source tags and inspectable local infrastructure matter; consider Overture Buildings/Transportation for standardized regional geometry.** These are alternatives and supplements, not three required global imports. Preserve OSM object type plus ID/version, or Overture GERS ID/release and applicable cross-release mappings. Overture and Geofabrik can share OSM ancestry, so agreement is not independent confirmation. [Geofabrik downloads](https://download.geofabrik.de/), [Overture buildings](https://docs.overturemaps.org/guides/buildings/), [Overture transportation](https://docs.overturemaps.org/guides/transportation/).

A footprint does not establish occupancy, ownership or current use. Road classes do not establish vehicle access at an incident time. Keep extracted tags; convenience GIS exports can lose parts of the source schema. Overture's transport theme is not a complete pipeline/electric-grid inventory. GHSL built-up rasters are optional modelled settlement context, not building registers. Defer TeleGeography structured submarine-cable data until its commercial licence and approximate route geometry suit an investigation; a public map does not grant a reusable route dataset. [GHSL data](https://ghsl.jrc.ec.europa.eu/download.php), [TeleGeography licensing](https://www2.telegeography.com/license-geocoded-map-data).

### Hazards and weather

**Use USGS and FIRMS for the first sensor-observation expansion after the X/imports/one-advisory workflow.** USGS event identity and update time support corrected earthquake revisions; preserve location/depth/magnitude semantics and the documented inclusive end time. FIRMS detections retain sensor, acquisition, footprint, processing version and quality fields; standard products may supersede near-real-time outputs. Neither a thermal detection nor a nearby earthquake establishes an attack or a damage assessment. Their bounded interfaces are already specified. [USGS query contract](https://earthquake.usgs.gov/fdsnws/event/1/), [FIRMS API](https://firms.modaps.eosdis.nasa.gov/api/area/).

IBTrACS is optional cyclone history: agency-derived best tracks and provisional tracks, not forecasts. Preserve source agency, wind averaging conventions, storm identity and track time; the archive documents early duplicate-track problems. ERA5 is optional bounded reanalysis for atmospheric context, not local station observation or future weather. Defer a new ISD weather adapter until assessing its GHCNh successor and the station-history workflow. [IBTrACS documentation](https://www.ncei.noaa.gov/products/international-best-track-archive), [ERA5 product](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview), [NOAA ISD](https://www.ncei.noaa.gov/products/land-based-station/integrated-surface-database).

### Imagery, elevation and land cover

**Retain the configured Sentinel-2 OGC viewer and add scene identity before advanced image analysis.** Sentinel-2 L2A surface reflectance is the preferred optical evidence product; preserve acquisition, tile, processing baseline and per-pixel masks. A tile-wide cloud percentage or successful PNG does not establish target visibility. The current CDSE STAC discovery root is `https://stac.dataspace.copernicus.eu/v1/`; catalogue queries supplement the existing viewer. Exact asset access, account requirements and service quotas are separate from public metadata. [CDSE STAC](https://documentation.dataspace.copernicus.eu/APIs/STAC.html), [Sentinel-2 products](https://documentation.dataspace.copernicus.eu/Data/SentinelMissions/Sentinel2.html).

Sentinel-1 GRD is an optional SAR complement requiring matched orbit/mode/polarization and explicit calibration/terrain treatment. Landsat Collection 2 Level-2 adds longer optical history with its own grid, scaling and QA. Co-register comparable acquisitions before interpreting changes; neither raw pixel difference nor model output establishes damage. [Sentinel-1](https://documentation.dataspace.copernicus.eu/Data/Sentinel1.html), [USGS Collection 2](https://www.usgs.gov/landsat-missions/landsat-collection-2-level-2-science-products).

Copernicus DEM GLO-30 is the preferred optional elevation product: a **surface** model, including vegetation/buildings, with an EGM2008 vertical datum. It is not a bare-earth or surveyed engineering surface. WorldCover 2021 v200 is useful optional land-cover context; it is a dated classification. Comparing 2020/2021 products mixes algorithm and physical changes. Defer Dynamic World until its model/probability interpretation and access are useful; consider JRC Global Surface Water for a specific water-history question, keeping cross-collection alignment limits. [Copernicus DEM](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM), [WorldCover](https://esa-worldcover.org/en/data-access), [Dynamic World](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_DYNAMICWORLD_V1), [JRC water history](https://global-surface-water.appspot.com/download).

### Conflict events and humanitarian reporting

**Use UCDP GED as an optional curated historical conflict layer; retain GDACS for the already planned disaster/advisory workflow.** UCDP v26.1 covers 1989–2025 and applies a defined lethal-organized-violence event concept, not all unrest or incident types. Keep persistent `id`, release, spatial/time precision and fatality ranges. `relid` may change and is not the persistent identity. The monthly Candidate product is provisional and separate. Source/reporting coverage and retrospective revisions limit absence and trend claims. [UCDP catalogue](https://ucdp.uu.se/downloads/), [current GED 26.1 codebook](https://ucdp.uu.se/downloads/ged/ged261.pdf).

GDACS alert episodes are evolving hazard/impact estimates; many underlying inputs overlap USGS and other sources, so do not count them as independent confirmations. ReliefWeb is useful optional document discovery, with report IDs distinct from disaster groupings and source publication distinct from archive update. Its read-only v2 API now requires a **pre-approved appname**. Keep partner-content rights with each document. [GDACS API](https://www.gdacs.org/Documents/2025/GDACS_API_quickstart_v2.pdf), [GDACS terms](https://data.gdacs.org/About/termofuse.aspx), [ReliefWeb API and quotas](https://apidoc.reliefweb.int/).

ACLED is an optional broader political-disorder source, subject to confirming the intended use under its current access/licensing terms. Preserve its event grain, precision, source and revisions. Defer GDELT from occurrence counting: it is better suited to discovery and media-attention questions. Keep Event and Mentions tables distinct; reporting volume is not incident frequency. [ACLED methodology](https://acleddata.com/methodology/acled-codebook), [ACLED terms](https://acleddata.com/eula), [GDELT data contract](https://gdeltproject.org/data.html).

### Legal entities, crosswalks and sanctions context

**Use bounded GLEIF lookups when an investigation needs legal-entity identity.** LEIs and same-jurisdiction registration identifiers are stronger starting points than names. GLEIF covers entities with LEIs, not every company; its accounting-consolidating parent relationships do not establish complete beneficial ownership or asset operation. Golden Copy/deltas are available if a local index later proves useful. Wikidata is optional multilingual context and a source of crosswalk candidates, retaining statement references, qualifiers and revisions. No world-sized entity graph is required. [GLEIF API](https://www.gleif.org/en/lei-data/gleif-api), [Golden Copy access](https://www.gleif.org/en/lei-data/gleif-golden-copy), [GLEIF terms](https://www.gleif.org/en/meta/lei-data-terms-of-use), [Wikidata structured dumps](https://www.wikidata.org/wiki/Wikidata:Database_download).

UN, OFAC and EU sanctions lists are optional, separate **dated authority assertions**. Preserve regime/programme, source record and legal-act links, amendments and delistings. A name hit is a candidate identity match; a listing does not establish guilt or beneficial ownership. Do not flatten the authorities into a timeless Boolean. Dataset reuse scope remains unresolved where the checked pages lacked explicit terms; the EU distribution locator returned 401 during research. These limits and acquisition locations are recorded in the catalogue. [UN consolidated list](https://main.un.org/securitycouncil/en/content/un-sc-consolidated-list), [OFAC list service](https://ofac.treasury.gov/sanctions-list-service), [EU official resources](https://finance.ec.europa.eu/eu-and-world/sanctions-restrictive-measures/overview-sanctions-and-related-resources_en).

### Population, settlement and displacement

**Prefer scoped GHSL GHS-POP R2023A for consistent population context; use WorldPop Global2 for a justified annual/country-specific alternative.** Both model residential distribution from demographic inputs. They do not observe who was present at an incident. GHSL includes five-year epochs, with 2025/2030 projections; WorldPop Global2 includes 2015–2030 annual estimates/projections. Preserve source census/model lineage, epoch, release, grid and NoData. Do not label a projected future year as measured population. GHSL-SMOD adds categorical settlement context derived from related inputs, not another independent population estimate. [GHSL product documentation](https://human-settlement.emergency.copernicus.eu/documents/GHSL_Data_Package_2023.pdf), [GHSL population access](https://human-settlement.emergency.copernicus.eu/download.php?ds=pop), [WorldPop Global2 release](https://data.worldpop.org/repo/prj/Global_2015_2030/R2025A/doc/Global2_Release_Statement_R2025A_v1.pdf), [WorldPop API v2](https://api.worldpop.org/v2/).

Counts, density and class codes require different aggregation. Sum valid **count** cells using a declared boundary-cell rule; convert density using compatible areas before totaling, and preserve counts when reprojecting. Treat settlement/land-cover codes categorically. NoData is unknown, not zero. Describe the resulting figure as estimated residential exposure within a chosen area/year, never as casualties, people currently present or precise person locations.

OCHA HDX COD population is an optional country-specific administrative source, requiring the actual resource licence, p-code/boundary edition and reference date. HDX is a catalogue with many contributors, not one harmonized dataset. UNHCR statistics are optional displacement context: preserve population type, origin/asylum geography and year, and distinguish end-period stocks from measured flows. Do not add overlapping categories or call a stock difference the number of people who moved. [HDX COD discovery](https://centre.humdata.org/ufaqs/how-do-i-find-the-common-operational-datasets-in-hdx/), [HDX licences](https://centre.humdata.org/ufaqs/data-licenses/), [UNHCR API](https://api.unhcr.org/docs/refugee-statistics.html), [UNHCR flow definitions](https://www.unhcr.org/refugee-statistics/insights/explainers/forcibly-displaced-flow-data.html).

## 3. Reconcile the inherited data

An earlier set of eight GeoJSON collections (ports, energy, nuclear sites, bases, air and naval bases, missile sites and chokepoints; 2,090 features) had incomplete provenance and no established licence. It is not included in the public repository; the reconciliation rules below describe how such a set would be promoted.

Reconcile ports first against WPI/UN/LOCODE, general airfields against OurAirports and energy records against appropriate GEM products. Match by source identifiers where available, then review name/type/location evidence; shared names or nearby coordinates only produce candidates. Keep unmatched records in a visibly unverified comparison collection. General-airport matches cannot validate military roles; PRIS cannot validate every inherited nuclear-site class. Military/naval/missile classifications and chokepoint interpretations need their own dated evidence.

No rows have been silently corrected, deleted, merged or promoted. Promotion attaches a publisher record/release, rights and provenance, precision and an explained crosswalk while retaining the original. Replace undated incident-like styling with separate dated evidence and analyst assessments when support exists. Preserve useful leads without presenting them as accepted facts.

## 4. Data lifecycle and acceptance

Treat reference geography, dated observations, event catalogues, registries and analyst assertions as separate families. Every promoted release needs a concrete source, version, rights basis, geographic/time scope and quality report. A generic provider name cannot supply those properties for all its products.

Use four states: **discovered → acquired/staged → accepted/published → retired**. Invalid or insufficiently documented material stays staged or in a review collection. Keep the last accepted release active when a refresh fails. A genuinely complete empty release may replace membership; a timeout, permission failure or partial page may not.

For each acquisition, retain the resolved asset/endpoint, request filters, publisher release/effective date, acquisition time, checksum, schema version, licence/attribution snapshot, expected/received counts, pagination or extraction bounds, coordinate reference system, geometry meaning, units, exclusions and quality findings. Mutable `latest` URLs and API metadata update times are not the dataset's vintage. A catalogue family must be expanded to a concrete product/release before acquisition.

Keep raw publisher snapshots immutable where retention permits. Normalized records refer to their exact source record and release. Display geometry and indexes are rebuildable views. Analyst annotations live separately. A new upstream release cannot overwrite notes, reinterpret an old citation or silently rewrite a saved brief.

A normalized record needs a namespaced publisher identifier, release reference, feature/entity class, original and language-tagged names, supplied aliases/codes with namespaces, geometry and precision/role, source assertion time or declared unknown, and quality flags. Preserve original fields alongside mapped ones. Codes retain leading zeros; a latitude/longitude point is not automatically a surveyed footprint or legal boundary. Unknown elevation/time/coverage is not zero.

Validate finite coordinates and axis order, geometry type, identity uniqueness within the provider namespace, dates/timezones, required fields, schema, counts/completeness and reviewable outliers. Country/region checks signal discrepancies; they cannot automatically relabel geopolitical claims. Check representative records against primary evidence before activating a new source family. Record acceptance criteria and observed results instead of one unexplained quality score.

Entity resolution produces candidates, confirmed aliases or unresolved relationships. Name/proximity alone cannot merge records. Plants can have multiple generating units; airports and military facilities can share a site; a port and city can share a name. Store the reason and source evidence for each confirmed crosswalk, supporting split/undo without destroying source records. Source dependencies also matter: Overture/Geofabrik, GHSL population/settlement and GDACS/USGS overlaps cannot manufacture independent confirmation.

Document rights by product and, where needed, source feature. Public visibility does not establish eligibility for every bulk acquisition, derivative database or redistribution. Unknown terms pause only the affected operation. Preserve required attribution in exports. This is a compact acquisition record within the application, not a new approval service or a required external governance platform.

## 5. Performance and refresh

Bootstrap selected areas and useful feature classes, then expand deliberately. Global names, buildings, roads and rasters should not be loaded eagerly into browser memory. Keep full geometries in retained data, spatial/lexical indexes for queries, and simplified shapes or tiles for display. Reduced display detail must not reduce analytical membership or totals.

Import in bounded batches, saving resume points after durable storage. Pin the accepted release while a candidate is staged; inspect schema changes, removals, geometry shifts and crosswalk effects before atomic replacement. Honour provider cadence instead of polling static releases like live feeds. Corrections and deletions are explicit changes. A partial or changed-schema response cannot masquerade as a complete empty snapshot.

Use regional extracts, time windows, resolution/product selection and bounded raster/catalogue queries. Preserve NoData, uncertainty, processing version and forecast/reanalysis/observation distinctions. A coarse raster resampled onto a finer grid gains no new measurement precision. A current reference cannot silently appear as historical truth in replay.

The [architecture's](../docs/ARCHITECTURE.md) concurrent-load, overload and cancellation gates apply to data imports. Dataset size alone does not justify extra services before measuring a bounded indexed implementation. Every optional source needs a named analyst question and a practical acquisition/refresh/retention budget.

## 6. How the developer uses this packet

Read this plan for decisions; look up selected entries in `catalogue.json` for precise access and semantic notes; use `docs/SOURCES.md` for the existing adapters. Catalogue `role` is interpreted within `delivery_stage`: a preferred source for a later module is not a global startup dependency. All entries are inactive research candidates. Their identity-field lists describe fields to preserve, not composite database keys. URL fields can be catalogues, templates, example releases or object prefixes; never execute a blind download loop over them.

For the first source import, produce one small accepted release with original input, normalized records and a quality report. Demonstrate unknown geometry/time, alias ambiguity, duplicate pages, a partial update and a corrected source revision. Exercise specification **A50**, keep the inherited archive unchanged, and show that old notes/citations survive replacement. Then expand according to the analyst workflow instead of the length of the catalogue.

Research deliberately stopped short of authenticated account setup, global downloads, numerical cross-provider benchmarking and real-world reconciliation of every inherited feature. Those are implementation-stage checks for selected products. The research improves source choice and the acceptance contract; it cannot certify that every source record is accurate, current or independently corroborated.
